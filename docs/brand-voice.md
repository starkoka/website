# 日本語の文体と編集手順

このサイトは、本人が制作物と活動を紹介する個人サイトです。制作物の仕組み、本人の担当、年次、成果、公開資料を、確認できる範囲で伝えます。第三者による人物評や広告文は書きません。

## 書く前に

1. `src/data/profile.json`、`projects.json`、`timeline.json`、`skills.json`と表示ページから事実を抜き出す。今回の整理は[事実台帳](copy-fact-inventory.md)を参照する。
2. 事実と評価を分ける。既存JSONの記載だけで、本人の現在の所属、個別の実装担当、導入先、制作物の現時点の動作まで確認できたことにはしない。
3. リポジトリ内に本人の執筆した記事本文や自己紹介文がある場合だけ、本人の文体の参考にする。現在のリポジトリでは特定できていないため、文体を推測しない。

## 文ごとの判断

最初に、その文がなくなると訪問者が何を知れなくなるかを考える。見出しを説明するだけの文、作品名と同じ情報を言い直す文、別のカードと同じ実績を載せる文は削る。必要な文だけを、元の構文にこだわらず書く。文章やカードの長さを揃えるための水増しはしない。

作品は機能を具体的に説明し、本人の担当とチームの成果を分ける。担当が確認できなければ「開発に参加」「共同開発」など、元データで裏付けられる範囲で書く。順位や受賞は大会名・年・個人かチームかを確認する。現在も続いているという主張は、最新の記録だけから推測しない。

## 編集後の検査

- 主語と作業・結果が読み取れるか。
- 抽象的な総括、広告的な形容詞、調査者の視点が残っていないか。
- 見出し、写真、前後の文章と同じ情報を繰り返していないか。
- 不自然な体言止め、英数字の機械的な空白、硬すぎる言い回しがないか。
- 他人のポートフォリオにもそのまま置ける文になっていないか。
- 削除した文にしかなかった事実やリンクが消えていないか。

です・ます調を基本とし、短さ自体は目標にしません。必要な説明が長くなることは許容します。情報不足は補作せず、確認事項として残します。
