# トップページ構成の比較

2026-09-27。既存ページを変更せずに比較するための静的HTMLモックです。
入口は `index.html`。ブラウザで直接開けます。画像は既存の `public/images` を相対参照します。
各案のリンク先は既存サイト `https://kokastar.dev` または既存の外部プロフィールです。

## 参考サイトの観察

https://brittanychiang.com/ をPlaywrightでPC・モバイル表示し、PCではスクロール後も確認。
PCの左側に名前・紹介・ページ内導線・外部プロフィールが残り、右側で経歴と制作物を読む。
モバイルでは縦積みになり、本人の情報に続いて本文を読む。
借りるのは「誰の制作かを見失わない配置」と、枠に頼らない情報のまとまり。
A案へ直接反映する。配色・英文コピー・職歴の構成をそのまま転用しない。

## 共通の判断

- 目的：訪問者が制作物と本人の役割を知り、詳細や外部プロフィールへ進めること。
- キャッチコピー、星評価、役割バッジの列は作らない。名前と事実から始める。
- 紫は識別色と操作色に使用。新しいロゴや架空の画像は作らない。
- 本人のアイコンを残し、写真は作品に結び付ける。写真に文章を重ねない。
- 各作品を同一の影付きカードに収めない。見出し・間隔・画像のまとまりで区切る。
- モック間の比較に必要な説明は比較ページに置き、ポートフォリオ本文には混ぜない。

## A：プロフィールを左に置く

情報順：本人情報・外部リンク → 制作物と担当内容 → 2025年の活動への参照。

```text
PC
[アイコン・名前       ][制作物と担当内容                 ]
[所属・短い紹介       ][ロボット小写真 | 役割と活動へのリンク]
[作品／活動／連絡先   ][IMEの画面     | 機能と制作へのリンク]
[GitHub・AtCoder      ][電卓の写真    | 構成と制作へのリンク]
  左はスクロール中も残る [2025年の活動・連絡先             ]

Mobile
[アイコン・名前・短い紹介・外部リンク]
[作品へのページ内リンク]
[作品名・担当内容 → 画像 → 詳細リンク] を縦に読む
```

写真は作品を見分けるための補助。実装時はモバイルで画像を本文直後に配置する。
特徴：情報を読み比べやすい。名前とGitHubへいつでも戻れる。
弱点：写真の迫力はBより弱い。スクリーンショットの細部は詳細ページで読む必要がある。
初案の「左に大きな抽象コピー＋右に写真」は既存トップに近いため不採用。

色：背景 #181522／本文 #f4f1fa／補助 #beb6cf／紫 #c4adff／線 #393145。
書体：日本語はNoto Sans JP優先のサンセリフ、名前は同系サンセリフ太字。
名前44px、作品見出し24px、本文15px・行高1.9。左揃え。左約1/3、右約2/3。

## B：制作物の写真から入る

情報順：横長の本人紹介 → 3つの制作物を画像中心に一覧 → 活動と連絡先。

```text
PC
[アイコン・名前・所属              GitHub／プロフィール]
[制作物                                              ]
[ロボットの縦写真（大）   ][Hizkの変換画面（横）        ]
[                        ][機能・開発内容              ]
[                        ][電卓の実物写真              ]
[役割・活動へのリンク    ][回路の説明・制作へのリンク   ]
[2025年の活動                           連絡先         ]

Mobile
[短い本人紹介]
[ロボットの作品名・役割 → 写真 → 詳しい説明]
[Hizk画面・機能]
[電卓写真・説明]
[活動・連絡先]
```

写真自体を構造に使い、ロボットの縦写真とソフトの横画面を同じ比率に揃えない。
特徴：実際に何を作ったかが視覚で分かる。写真と担当説明が離れない。
弱点：モバイルでは長くなる。ロボットの比重が強く、文章を比較する速度はAより遅い。
初案の同サイズ3カードは不採用。素材の縦横比と情報量で面積を変える。

色：背景 #ffffff／本文 #25222d／補助 #605c69／紫 #6543a9／薄紫 #f0ebf8／線 #ded9e6。
書体：Aと同じ系統。名前30px、ページ見出し36px、作品見出し26px、本文15px・行高1.9。
左揃え。最大幅1160px。写真は影なし、説明を外側に置く。

## C：制作の記録を読む

情報順：本人紹介 → 年が確認できる制作・活動を新しい順 → 全制作物・活動履歴・連絡先。

```text
PC
[アイコン・名前・紹介                 外部プロフィール]
[制作の記録                                            ]
[2025][ロボコン：本人の役割・参加記録    ][小写真2枚       ]
[2024][Hizk：機能・開発内容              ][変換画面        ]
[2023][祗園祭Webサイト：共同開発                          ]
[全制作物・活動履歴・連絡先                               ]

Mobile
[本人紹介]
[年 → 作品名 → 担当・内容 → 小写真]
[年 → 次の作品 ...]
```

写真は説明に添える資料。大きなヒーロー写真を置かず、全体像から担当へ読む。
特徴：制作の蓄積と役割の変化が分かる。画像のない共同制作も無理なく置ける。
弱点：ビジュアルの第一印象は控えめ。制作年不明の作品はこの抜粋に載せにくい。
日付は実績・制作の記録の日付であり、写真の撮影年を表すものではない。
装飾的な縦線・交互配置のタイムラインは使わず、短い記録として揃える。

色：Bと同じ。配色でなく情報構造の差を比較する。
書体：Bと同じ系統。名前30px、ページ見出し30px、作品見出し24px、本文15px・行高1.9。
左揃え。最大幅1040px。年／説明／資料の3列を、モバイルでは1列にする。

## 文言の根拠と掲載範囲

外部で実績を再照合したものではなく、以下のリポジトリ内の記録を根拠とする。

| 掲載内容 | 根拠 | 扱い |
| --- | --- | --- |
| 名前・アイコン・所属・外部プロフィール | `src/data/profile.json` | 既存記載を使用。2026年の学年は推測しない |
| ロボコンのマネージャー・制御・操縦、2025年全国大会 | `src/data/timeline.json` の2025-11、`projects.json` | チームの成果と本人の役割を区別 |
| Hizkの意味からの変換、Mozc、GPT-4、優秀賞 | `src/data/projects.json`、`timeline.json` の2024-03 | 個人の実装担当箇所までは断定しない |
| StellarculatorのRaspberry Piと自作加減算回路 | `src/data/projects.json` | 詳細な担当分担・制作年は加えない |
| 祗園祭Webサイト2023の共同開発 | `src/data/projects.json` | デザイン担当などの分担は追加しない |
| DIVER OSINT CTF 2025の全体5位 | `src/data/timeline.json` の2025-06 | チーム名と併記 |

写真は全て既存の作品画像。写真の撮影年・機体名・写っている部品の設計担当は特定しない。
Hizkは現在動作する公開サービスとは表現しない。担当が分かるロボコンの記述を各案で優先する。

## 比較の目安

Aは人物と作品を並べて読む、Bは実物を見る、Cは担当と年を追う。
まずAとBのどちらの読み方がこのサイトに合うかを比較し、活動の蓄積を重視するならCを選ぶ。
簡易モックの段階なので、既存ページへの適用・テーマ切替・動的データ連携は実施しない。


## 表示と操作の確認

Playwright / Chromeで3案それぞれ1440px・390px・320px幅を表示。9ケースで横方向のはみ出しなし、全画像の読み込み成功、h1は各1件。
PC・モバイルの全体画像を `screenshots/` に保存し、目視確認した。
比較ページのA/B/C切替と390pxプレビュー切替も確認済み。
画像を優先するB案でも担当がすぐ分かるよう、ロボコンの作品名と役割は写真の前へ配置した。
結果は `checks.json` と `interaction-checks.json`。外部リンク先の現在の稼働は検証対象外。
既存の `src/`、`components/`、設定ファイルは変更していない。
